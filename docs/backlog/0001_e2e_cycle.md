# Backlog 0001 — Первый E2E нейросимволического цикла (ERC-4626 `deposit`)

- **Связан с:** [ADR-0001](../adr/0001_neurosymbolic_erc4626_deposit.md), [research_insights](../insights/fv_and_agentic_development.md)
- **Дата:** 2026-06-19
- **Тип:** Research backlog — прогрессивная детализация (M(-1)/M0 подробно; M1–M3 плейсхолдеры, уточняются после Фазы 0)

## Зафиксированные решения (см. сессию планирования)

1. **E2E-стратегия — строго по фазам ADR 0→3.** Без walking-skeleton со stub-заглушками. Фаза 0 доводится до реального вердикта прежде, чем подключать агентов по одному. «Первый E2E полного цикла» = критерий успеха Фазы 3 (петля прошла end-to-end ≥1 раза на `deposit`, выдав *какой-то* вердикт + классификацию — не обязательно `proved`).
2. **Эталон — два уровня.** Tier-1: минимальный самодостаточный ERC-4626 vault (`deposit`, округление вниз, без rebasing/rayMul) → baseline «труба замыкается». Tier-2: реальный Aave `ATokenVault` (rayMul/rayDiv) как намеренная стена-бенчмарк.
3. **LLM-доступ — Claude Agent SDK / субагенты** (модули [1][2][3]). Воспроизводимость замера (фиксация модели/seed) — открытый риск, см. реестр ниже.

## Рекомендации по инфраструктуре (low-stakes, подтвердить по ходу)

- **Оркестрация — Python 3.12** (есть): glue для запуска `solc`, парсинга вердиктов, вызова субагентов, сбора метрик.
- **Solidity-сторона — Foundry-проект** (`forge` 1.2.3 есть): сборка/пин solc, эталонные контракты, harness-контракты.
- **Расположение — новый top-level каталог `cycle/`**, изолированно от `landing/`/`site/`. Структура задаётся в T-03.

## M(-1) — Foundation (до Фазы 0)

Сначала спайки, снимающие мои «не знаю»; всё остальное от них зависит.

### T-01 · SPIKE · 🆕 SMT-бэкенд реально работает на этой машине

- **ADR:** модуль [5] · Фаза 0 · §5.5 (решение о ядре).
- **DoD:** установленный `solc` (через foundry/`svm` или brew; при нужде `brew install z3`); закоммичены два примера — тривиальный `assert`, который SMTChecker **доказывает**, и тривиальное нарушение, которое он **ловит контрпримером**; в README зафиксированы версия solc, движок (`bmc`/`chc`), какой солвер использован.

- **Deps:** T-02.

### T-04 · SPIKE · 🆕 Выразим ли экономический инвариант в SMTChecker
- **Цель/переменная:** проверить неявное напряжение — в SMTChecker нет ghost-переменных и storage-hooks (как в CVL), поэтому `sum(balances) == totalSupply` может быть **невыразим без harness**. Это бьёт в гипотезу ADR «экономику генерить легко» ещё до Фазы 2.
- **ADR:** [1][2] · Фаза 0/1 · §5.2 (разделение слоёв) · риск «доказуемость ≠ корректность».
- **DoD:** на минимальном vault — ответ да/нет + какой механизм потребовался (трекаемая сумма в обёртке? квантор по mapping? только CHC-движок?); вывод фиксируется как первый экспонат «карты стен».
- **Deps:** T-01, T-10.
- **Открытые вопросы:** пределы поддержки кванторов по mapping в CHC-движке SMTChecker — **не уверен, измеряем**.

### T-05 · BUILD · 🆕 Завести ground-truth (Aave CVL + ATokenVault)
- **Цель:** вендорить эталон для [6] и Tier-2; сеть до GitHub доступна (HTTP 200).
- **ADR:** [6] · §5.4 (ground-truth дельта).
- **DoD:** под `cycle/ground_truth/` лежат: CVL-спеки Aave Vault из replication-package PropertyGPT (`totalSupply_EQ_sumAllBal`, ghost `rayMul`/`rayDiv` и т.д.) и исходник `ATokenVault`, с зафиксированными commit-хешами/provenance.
- **Deps:** T-03.

### T-06 · BUILD · 🆕 Детерминированный раннер+парсер вердиктов (ядро [5])
- **Цель:** обёртка над `solc --model-checker-*`, дающая структурированный вердикт `{proved | counterexample+witness | inconclusive(timeout|k-bound)}`. Это и harness ядра, и фундамент всех замеров.
- **ADR:** [5] · §5 (измерение).
- **DoD:** на входе `.sol` + конфиг движка → JSON-вердикт; логируются версии solc/солвера, движок, timeout, k-bound — для воспроизводимости research-замера.
- **Deps:** T-01, T-02.

### T-07 · BUILD · 🆕 Контракты интерфейсов модулей [1]–[6]
- **Цель/переменная:** зафиксировать I/O-схемы каждого модуля сейчас, чтобы каждый был отключаемым/измеримым в изоляции (§2.4). Без этого «измерение вклада каждого модуля» нереализуемо.
- **ADR:** §2.4 · §5.1 (карта стен).
- **DoD:** JSON-схемы вход/выход для [1][2][3][4][5][6] + no-op заглушка на каждый модуль, соблюдающая контракт (заглушки — только каркас интерфейса, НЕ для сквозного прогона: см. решение №1).
- **Deps:** T-03.

## M0 — Фаза 0: доверенное ядро на ручных спеках (агентов нет)

Принцип ADR: «сначала доказать, что труба не течёт». Калибровка стены до вложений в LLM.

### T-10 · BUILD · Минимальный ERC-4626 vault (Tier-1)
- **Цель:** объект, на котором труба гарантированно может замкнуться — один `deposit`, округление вниз assets→shares, без rebasing/rayMul.
- **ADR:** §2.2 · Фаза 0 · §5.3 (baseline аудита).
- **DoD:** компилируется под пиннутым solc; покрывает оба интересующих слоя (функциональный: корректность округления/overflow; экономический: доли пропорциональны активам).
- **Deps:** T-02.

### T-11 · BUILD · Ручная спека + harness для Tier-1
- **Цель:** человек вручную пишет экономический инвариант + функциональный harness (pre/post, overflow-обвязка) как Solidity assert/harness-контракт.
- **ADR:** [1][2] вручную · Фаза 0.
- **DoD:** артефакт спеки+harness, привязанный к T-10.
- **Deps:** T-10, T-04.

### T-12 · MEASURE · Прогон Tier-1 через [4]→[5]
- **Цель:** критерий Фазы 0 — ядро вообще доказывает `deposit`.
- **ADR:** [4][5] · Фаза 0 · §5.3, §5.5.
- **DoD:** реальный вердикт `proved` (цель) либо задокументированное «почему не вышло».
- **Deps:** T-06, T-11.

### T-13 · MEASURE · 🆕 Карта стен SMTChecker на Tier-1
- **Цель/переменная:** систематически нащупать, где упирается ядро — k-bound, циклы, деление/округление. Менять по одной переменной.
- **ADR:** [5] · Фаза 0 · **§5.1 (карта стен — главная ценность)** · риск k-bound.
- **DoD:** первая карта ограничений SMTChecker на ERC-4626 (что/когда ломается).
- **Deps:** T-12.

### T-14 · MEASURE · 🆕 Стена на арифметике Aave (Tier-2)
- **Цель:** навести ту же ручную методику на реальный `ATokenVault.deposit` (rayMul/rayDiv) — намеренный бенчмарк стены.
- **ADR:** [5][6] · Фаза 0 · §5.1, §5.5 · риск «стена ghost-арифметики».
- **DoD:** задокументировано, где именно SMTChecker ломается на арифметике Aave; вход для решения §5.5 (держим SMTChecker или нужен Certora/theorem-proving путь).
- **Deps:** T-13, T-05.

### T-15 · SPIKE · 🆕 Метод сравнения CVL ↔ SMTChecker
- **Цель/переменная:** определить, *как* мерить «близость к эксперту», если ядро — SMTChecker (Solidity assert), а эталон — CVL (ghost+axiom+`requireInvariant`). В ADR метод не задан.
- **ADR:** [6] · §5.4 (ground-truth дельта).
- **DoD:** задокументированная процедура/метрика (пусть грубая — напр. чек-лист соответствия CVL-конструкций present/absent в SMTChecker-harness).
- **Deps:** T-05, T-13.

**Выход M0 / Фазы 0:** труба замыкается на Tier-1 (`proved`); карты стен для Tier-1 и Tier-2; метод сравнения с ground-truth; собран вход для §5.5.

## M1 — Фаза 1: Economic Spec Generator [1] (плейсхолдер, уточнить после M0)

- Реализовать [1] как Claude-субагента: вход `deposit` + доменный контекст ERC-4626 → экономический инвариант. Harness по-прежнему ручной.
- **MEASURE:** качество инварианта vs ground-truth [6]; проверка гипотезы «экономику генерить легко» (с поправкой на вывод T-04).
- Несколько прогонов → замер стохастичности покрытия (риск §7).
- **Открытый вопрос:** воспроизводимость прогонов субагента (фиксация модели/seed) — из решения №3.

## M2 — Фаза 2: Functional Harness Generator [2] (плейсхолдер)

- Реализовать [2] как субагента: метод + инвариант → proof harness (ghost-арифметика, pre/post, overflow-обвязка).
- **Центральный научный результат:** где и как часто ломается автосинтез harness (§5.1, §5.2).
- **Зависит от T-04:** если ghost-абстракция арифметики в SMTChecker не выражается как в CVL — переформулировать, что вообще считается «harness» в этом ядре.

## M3 — Фаза 3: замыкание петли + классификатор [3] (плейсхолдер)

- Полный автопроход [1]→[2]→[4]→[5]→[3]. Классификатор [3] в 1-м цикле допустимо полуручной (ADR §2.1/§8).
- **Критерий успеха (он же «первый E2E полного цикла»):** петля прошла end-to-end ≥1 раза на `deposit`, выдав вердикт + классификацию.
- **DoD цикла:** произведены все 5 выходов §5 (карта стен, измерение разделения слоёв, baseline аудита, ground-truth дельта, решение о ядре).
