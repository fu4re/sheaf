# Task 0014 — Библиотека нелинейных лемм ↔ ядро TCG: снять SMTChecker-стену переиспользуемо (масштаб, не один контракт)

- **Дата:** 2026-07-02 · **Тип:** capability build + e2e-замер (масштабирование, judge=solver/ядро)
- **Опирается на:** [Finding 0008](../findings/0008_neural_lean_prover_ghost_axioms.md) (нейро-провер = untrusted-генератор за ядром Lean, 5 новых разрядок) · [Finding 0004](../findings/0004_assume_guarantee_cross_contract.md) (майнинг обязанности + `havoc`+`require(G)` разрядка) · [Finding 0005](../findings/0005_vacuity_gate_mutation.md) (Probe R/M, дуальный spurious-counterexample) · [Finding 0007](../findings/0007_assurance_package_format.md) (assurance-пакет, лист `proven` vs `assumed`) · [план tcg CLI](../plans/adr-federated-parrot.md) (§ Q3 verify-level, § Acceptance) · ADR-0003 (роли I/K, trusted core)
- **Зависит от:** предстартовые блокеры Фазы 0 (NeuralProbeCheck-репро + axiom-аудит в package) · промоушен 5 лемм из `NeuralProbe.lean` (Step 0, внутри Фазы 3) · **Разблокирует:** T4 (масштаб на реальном протоколе) — снимает *первую измеримую* способностную стену (нелинейка); T4 сверх неё = графы вызовов (havoc-стена, Trace-deep) — отдельный слой, 0014 его не закрывает
- **TL;DR:** SMTChecker захлёбывается на нелинейной арифметике (`var·var`, floor-деление) → любой реальный DeFi-контракт даёт `⊥_gen` (замерено: [ProportionalVault-T0008](../../cycle/measurement/artifacts/tcg_runs/ProportionalVault-T0008/) — POST `totalShares ≤ totalAssets`, `reason: nonlinear arithmetic — the SMTChecker wall`). Приём — доказать нужный арифметический факт **один раз в Lean** (ядро судит, ноль добавленного доверия) и скормить SMTChecker'у как `havoc`+`require(lemma)`-абстракцию. **Гипотеза масштаба:** словарь DeFi-арифметики крошечный (≈1 базовая операция `mulDiv` + ≈5 семейств лемм), поэтому **одна лемма снимает стену у КЛАССА контрактов**, а не у одного. Эта задача превращает приём из локального трюка в **переиспользуемую библиотеку лемм, бесшовно связанную с K-гейтом**, и **измеряет множитель** «фикстур на лемму» — то есть проверяет, продукт это (оплачено однажды, размазано на все) или сервис (труд на каждый контракт).

---

## Зачем (одно предложение)

Нелинейная стена SMTChecker'а — **первая измеримая** *способностная* преграда на пути к e2e на реальном протоколе (T4). T4 сверх неё требует и **графов вызовов** (реальные протоколы = call-graphs + нелинейщина, [roadmap T4](../mvp_roadmap.md)), которые 0014 не закрывает — но нелинейка бьёт первой и измеримо (ProportionalVault → `⊥_gen`); если её снимает **общая библиотека kernel-проверенных лемм** (а не доказательство-с-нуля на каждый контракт), у TCG появляется продуктовый рычаг — это и надо измерить, а не предположить.

## Гипотеза (что именно проверяем — это про МАСШТАБ)

**H1 (рычаг):** ≈5 семейств лемм над ≈1 базовой операцией (`mulDiv`) покрывают подавляющее большинство нелинейных `⊥_gen` на нашем корпусе — приём масштабируется (продукт).
**H0 (честный негатив):** покрытие длиннохвостое — каждый контракт тянет свою уникальную лемму ⇒ приём локален (сервис). Ценный результат (граница переиспользования), записывается прямо.

**Предзаданные параметры замера (ЗАФИКСИРОВАНЫ ДО прогона — иначе вывод product-vs-service подгоняется под данные):**

| Параметр | Значение (зафиксировано) |
|---|---|
| **Corpus** | только рукописные фикстуры: `cycle/contracts/**`, `cycle/trusted/harness/**`, `cycle/trusted/smt_smoke/**`, `cycle/ground_truth/*/src/**`. **Исключены** `measurement/artifacts/**`, `naive_loop/runs/**`, `lib/forge-std/**`, build-выхлопы. Замораживается в `corpus.txt` (content-hash каждой) **до** Фазы 1 |
| **Дедупликация** | контракты схлопываются по content-hash; семья мутантов (напр. `MiniERC20Delta`-family) считается как **один** элемент, не по мутанту (иначе reuse завышен) |
| **Критерий «одна лемма»** | две фикстуры делят лемму ⟺ инжектнутое **Lean-утверждение идентично** (та же теорема + те же side-conditions), НЕ «та же операция» |
| **Множитель M** | max по леммам от (# различных не-мутантных контрактов, разблокированных этой леммой) |
| **Покрытие C** | доля нелинейных-`⊥_gen` фикстур замороженного corpus, снятых каталогом ≤5 семейств |
| **Порог H1** | **M ≥ 3 И C ≥ 60 %** (какой-то леммой реально переиспользуют + каталог покрывает большинство). Иначе **H0** — записать, что именно не добрало |

Судья — солвер (`tcg check` → Accept/⊥) и ядро Lean (`lake build` + `#print axioms`). Гипотезу закрывает **измеренный M/C против предзаданного порога**, не рассуждение.

## Таксономия класса (5 семейств — структура для Фазы 2)

1. **Границы/монотонность** — `mulDiv_le_left`, `rayMul_lower/upper`, `rayDiv_upper/lower` → инварианты «долей ≤ активов».
2. **Тесность/округление** — `mulDiv_mul_le`, `mulDiv_tightness` → «округление не создаёт ценность».
3. **Нуль/край** — `mulDiv_eq_zero` → базовые случаи, первый вклад.
4. **Дистрибутивность/консервация** — `ar_delta`, `transfer_sum_preserved` → «сумма сохраняется».
5. **Overflow side-condition** (`x·y < 2^256`) — мост ℕ↔256-бит слово. **Ещё не атаковано — см. ловушку №1.**

Фазы 1→2→3→4 последовательны по смыслу. Каждая — перепроверяемый артефакт; honest-negative первым классом. **Фаза 0 — предстартовые блокеры (High-аудит): без них Step 0 и bridge несоундны.**

Без этого таргета «build-pass ≠ proof» не проверялся вообще, и Step 0 промоутил бы вслепую. **Фикс применён** (`open AaveArith` в `NeuralProbeCheck.lean`) и **подтверждён ядром**: `lake build …NeuralProbeCheck` rc=0; все 8 теорем `⊆ {propext, Classical.choice, Quot.sound}`; `sorry_demo` → `[sorryAx]` (контраст работает). Finding 0008 снова воспроизводится.

**Б2 — axiom-аудит в `package`/bridge, не только build rc (High) — ✅ СДЕЛАНО, судья=ядро (2026-07-03).** Была дыра: `package.py` ставил `status: "proven" if build_status=="ok"` — по одному `lake build`, **без** `#print axioms`/`sorryAx`. **Реализовано и провалидировано:**

### Фаза 1 — Перепись и таксономия (измерить класс и множитель)

- **Цель:** превратить grep-оценку в «N по факту» на **замороженном canonical corpus** (`corpus.txt`, не generated-выхлопы) + измерить множитель M / покрытие C.
- **Как:** прогнать `tcg check` (или прямой `solver.run_solver`) по фикстурам; собрать **каждый** `⊥_gen` с `reason` = nonlinear; вынуть точное недоказанное verification condition (майнинг обязанности, идиома [Finding 0004]); кластеризовать по (операция × форма границы) в 5 семейств; хвост записать отдельно.
- **Скоуп-старт:** пилот на 16 fixed-point-фикстурах (дёшево), затем расширение на нелинейно-формные по мере бюджета.
- **Артефакт:** `docs/findings/artifacts/lemma_census.md` (таблица: семейство → #фикстур → нужная лемма) + машинный `lemma_map.json` (фикстура → семейство → лемма-id).
- **DoD:** число класса уточнено эмпирически; множитель измерен; длинный хвост (некластеризуемое) назван честно. H1 vs H0 — предварительный вердикт по данным.

### Фаза 2 — Формулировки лемм (структурирование, откуда берём)

Три дисциплинированных источника, **не ad hoc** (по приоритету):
1. **Из провалившегося VC солвера** — первичный, систематический, автоматизируемый: на чём захлебнулся SMTChecker, то и кандидат-лемма.
2. **Из опубликованных spec-библиотек** (Certora/Aave/Compound) — они *уже постулируют* эти границы аксиомами (Finding 0008: rayMul/rayDiv-границы = «ровно то, что постулирует Certora»). Готовый каталог.
3. **Из Mathlib** — лёгкие инстанцируются (`mulDiv` = `Nat.div_mul_le_self`).

- **Артефакт:** `lemma_catalog.yaml` — на каждую лемму: Lean-формулировка (точно совпадает с SMT-абстракцией!), источник, **side-condition** (overflow-мост, кванторная форма), обслуживаемые фикстуры.
- **DoD:** у каждой записи назван источник **и** side-condition; **ни одной леммы без явного overflow/квантор-кавеата** (иначе Фаза 4 несоундна).

### Фаза 3 — Доказать (Lean, судит ядро)

- **Step 0 (после Б1, уже заработано Finding 0008):** промоушен 5 лемм `NeuralProbe.lean → Basic.lean`; сдвиг 4 пунктов `not_yet_discharged → discharged` в `axiom_registry.json`. Осознанный trusted-base-коммит (не молча из experiment-файла — так требует сам F0008). **Гейт промоушена — чистый axiom-аудит (Б1), а не только build rc.**
- **Как:** непокрытые семейства атаковать методом Finding 0008 (нейро-провер = untrusted-генератор за ядром Lean); каждый успех переводит лист `assumed → lean_theorem(proven)` — **сужает** trusted base.
- **DoD:** лемма `proven` **только** если `lake build` rc=0 **и** `#print axioms ⊆ {propext, Classical.choice, Quot.sound}` (без `sorryAx`). Сопротивляющиеся (forall-леммы, overflow-мост) — записать как границу, не замолчать.

### Фаза 4 — Бесшовное e2e-связывание с ядром TCG («lemma bridge»)

Настоящая интеграция в K-гейт:
- *(a)* `tcg/commands/check.py` детектит нелинейный VC (`inconclusive` + nonlinear-reason) → *(b)* ищет подходящую лемму в `lemma_catalog.yaml` → *(c)* эмитит SMT-абстракцию (`havoc` нелинейного терма + `require(lemma)` в Solidity-форме) → *(d)* перегон `run_solver` → **Accept** → *(e)* `tcg/commands/package.py` привязывает лист к Lean-теореме (`lean_theorem`/proven), trusted base строго меньше, чем без леммы.
- **DoD:** e2e на **≥3 фикстурах из ≥2 семейств**: `tcg run` → Accept, package WELL-FORMED, лист леммы = `proven` **только под чистым axiom-аудитом (Б2), не по build rc**, `--replay` воспроизводит. Bytecode-identity **всё ещё открыт** — приём его не трогает, сказать явно (`⊥_assumptions_open` остаётся, если открыты другие dischargeable-листы — green не обещаем этой задачей).

## Две soundness-ловушки — это и есть «сделать правильно» (иначе весь приём = false-green)

Проверять **механически**, не на глаз:

1. **Overflow-мост (ℕ ↔ 256-бит слово) — РИСК №1.** Леммы над ℕ (floor-деление без переполнения); SMTChecker над 256-битным словом. Инжектнуть ℕ-лемму как word-`require` **без разрядки `x·y < 2^256` — несоундно** (это `trusted_base_caveat` реестра). Фаза 4 обязана либо разрядить non-overflow отдельной обязанностью, либо оставить её **видимым** `assumed`-листом с `risk_if_false` — не молча поверить.
2. **Совпадение формы (spurious-дуал, Finding 0005).** `havoc`+`require` обязаны совпасть с кванторной формой инварианта; инжектнутый `require(lemma)` = **точно** доказанная лемма (то же утверждение), не прокси (ловушка conservation≠delta, Finding 0004). Probe M ([cycle/measurement/vacuity.py](../../cycle/measurement/vacuity.py)) обязан подтвердить, что абстракция **не вакуумна** (иначе лемма «доказывает» пустоту).

Bridge эмитит и Lean-утверждение, и его Solidity-`assume`-форму + сверку соответствия — соответствие не предполагается.

## Риски / открытые / что НЕ закрываем

- **H0 возможен** — если хвост толстый, приём локален; записываем честно (это и есть измерение).
- **Overflow-мост может не разрядиться механически** на source-level → часть лемм останется `assumed` с кавеатом (не тихо proven).
- **Bytecode-identity / faithfulness (moat #1) — вне скоупа.** Эта задача снимает *способностную* стену (нелинейка), не *faithfulness*-стену; `⊥_assumptions_open` остаётся легитимным исходом.
- **Автономный G/I-loop — вне скоупа** (bridge инжектит лемму, но контракт по-прежнему вайб-кодится снаружи).
- **CHC kernel-recheck (`A_solver`) — вне скоупа** (Finding 0007 DoD#3, отдельный трек).

## Маппинг на роадмап

Снимает **нелинейную стену T4** (масштаб на реальном протоколе) — необходимый первый инкремент, не полное закрытие T4 (для этого нужен e2e на задеплоенном мульти-контрактном срезе). Косвенно готовит T6 (любой живой DeFi-код нелинеен). Продуктовый тезис, который задача доказывает или опровергает: **трудная арифметика домена — оплаченный-однажды общий актив** (⇒ продукт), а не труд-на-каждый-контракт (⇒ сервис) — прямой вход в развилку T3.
