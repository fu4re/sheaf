# ADR-0001 — Нейросимволический цикл формальной верификации для ERC-4626 `deposit`

- **Статус:** Proposed (research, не продуктовое решение)
- **Дата:** 2026-06-19
- **Контекст-артефакт:** `research_insights.md` (6 источников)
- **Тип:** Research Decision Record — фиксирует, *что мы решили попробовать и почему*, а не *что построить в продакшн*

---

## 1. Контекст

Лаборатория ставит на агентскую разработку Solidity-контрактов, доказуемую через нейросимволическую модель (агент генерирует — символьное ядро доказывает). Нарратив и инсайты зафиксированы в `research_insights.md`. Прежде чем заявлять тезис вовне и масштабировать, нужно **эмпирически проверить, насколько далеко мы реально можем дойти** на максимально узком срезе.

Из разбора источников вытащены три факта, определяющие это решение:
- Генерация однострочного инварианта почти решена рынком (PropertyGPT, 80% покрытия) — узкое место не там.
- Реальная сложность — в **proof harness** (ghost-арифметика `rayMul`/`rayDiv`, overflow-обвязка, лемма-цепочки): на спеках Aave Vault это ~90% объёма и ~100% сложности.
- Паттерн «agents propose, solvers verify» подтверждён как рабочий на двух языках (Agentic Model Checking, май 2026), но его главный нерешённый failure mode — «слишком слабая невидимая спека» — это ровно наш риск «доказуемость ≠ корректность спеки».

Это research-цикл, не MVP. Задача — **пройти цикл и понять границы**, а не выпустить инструмент.

---

## 2. Решение (что именно делаем)

Реализуем **полный нейросимволический цикл верификации на одном методе** — `deposit` из ERC-4626 (эталон: `ATokenVault` от Aave) — в **режиме аудита** (`код → спека → доказательство`).

Четыре зафиксированных решения:

### 2.1. Режим — АУДИТ, не синтез
`код → спека → доказательство`. Причина: для аудита есть готовый эталонный код Aave Vault и готовые доказанные CVL-спеки как ground truth. Синтез (`спека → код`, наш будущий дифференциатор) на первом цикле невалидируем — не с чем сравнивать. Аудит даёт baseline, без которого синтез измерять невозможно.

### 2.2. Метод — `deposit`
Причина: классический срез с нетривиальным округлением вниз (assets → shares), на котором сходятся оба интересующих нас слоя — функциональный (корректность округления, отсутствие overflow) и экономический (доли выпускаются пропорционально активам, без создания стоимости из воздуха). Достаточно сложен, чтобы упереться в стену harness, но достаточно мал, чтобы пройти end-to-end.

### 2.3. Символьное ядро — SMTChecker (встроен в solc), CVL как эталон
**Решение:** доказываем на **SMTChecker**; доказанные **CVL-спеки Aave используем как ground truth для сравнения, НЕ как движок.**

Обоснование выбора (рассмотренные альтернативы):

| Кандидат | За | Против | Вердикт |
|---|---|---|---|
| **Certora / CVL** | Родной для ERC-4626; есть готовый эталонный harness Aave дословно | Проприетарный, нужен доступ/грант; движок — чёрный ящик, нет чистого контрпримера; агент должен генерить редкий CVL | Эталон, не ядро |
| **CBMC / BMC** | Открытый, даёт контрпримеры | Не родной для Solidity → нужен слой трансляции (тот самый разрыв модель↔байткод из Tolmach) → инфраструктурный ад до первой петли | Отклонён для 1-го цикла |
| **SMTChecker (solc)** ✅ | Встроен в компилятор (нет трансляции, работает на `.sol`); Z3/cvc5 под капотом — честное ядро (BMC + CHC); бесплатный; спека = `assert` в Solidity (язык, которого море в обучении LLM) | Слабее Certora на глубоких инвариантах; плохо тянет циклы (k-bound); упрётся в стену ghost-абстракций на `rayMul` | **Выбран** |

Ключевой довод: для research-цикла критерий ядра — **«что замкнёт петлю с минимумом инфраструктуры»**, а не «что лучше для продукта». SMTChecker убирает слой трансляции и ведёт к стене быстрее всех. А **упереться в стену ghost-абстракций арифметики Aave — это и есть научный результат первого цикла**, а не провал.

### 2.4. Архитектура — модульная, разрез по ЛИНИИ ДОВЕРИЯ
Граница модулей проходит не по задачам, а по линии доверия: каждый модуль либо «предполагает» (LLM, недоверенный, может галлюцинировать), либо «доказывает» (детерминированный, доверенный). Между мирами — детерминированный шлюз. Это даёт возможность выдёргивать/отключать любой ненадёжный модуль, не трогая ядро, и измерять вклад каждого — главный инструмент картографирования стен.

Инсайт о разделении функционального и бизнес-пруфа встроен в структуру: генератор спеки — это **два независимых модуля** (экономический и функциональный), потому что мы подозреваем, что стена у них в разных местах (экономику LLM генерит легко, функциональный harness — трудно), и в одном модуле это не измерить.

## 3. Архитектура цикла

```
        МИР «ПРЕДПОЛАГАЕТ» (LLM, недоверенный)          ШЛЮЗ            МИР «ДОКАЗЫВАЕТ» (доверенный)
        ─────────────────────────────────────       ───────────       ─────────────────────────────

  [1] Economic Spec Generator ──┐
      (экономический инвариант)  │
                                 ├──> [4] Translator/Validator ──> [5] Solver Core (SMTChecker)
  [2] Functional Harness Gen ───┘     (→ assert/invariant Solidity,    │  proved / counterexample+witness
      (ghost-арифм., pre/post,         детерминир. проверка компиляции) │  / inconclusive (timeout, k-bound)
       overflow-обвязка)                                                │
                                                                        v
  [3] Counterexample Classifier <───────────────────────────────── (контрпример)
      (реальный баг / артефакт harness / слабый инвариант)

        ВНЕ ПЕТЛИ (измерение):
  [6] Ground-Truth Comparator — сверка [1]+[2] с эталонными CVL-спеками Aave (research-метрика)
```

### Модули

**Мир «предполагает» (LLM):**
1. **Economic Spec Generator** — вход: `deposit` + доменный контекст ERC-4626. Выход: экономический инвариант (бизнес-пруф). *Гипотеза: легко (≈PropertyGPT 80%).*
2. **Functional Harness Generator** — вход: метод + инвариант. Выход: proof harness (ghost-абстракции арифметики, pre/post, overflow-обвязка) — функциональный пруф. *Гипотеза: здесь стена.*
3. **Counterexample Classifier** — вход: контрпример от ядра. Выход: классификация (реальный баг / артефакт harness / слишком слабый инвариант). В 1-м цикле допустимо полуручной; место в архитектуре забронировано.

**Шлюз (детерминированный):**
4. **Translator/Validator** — переводит спеку агента в `assert`/инварианты Solidity для SMTChecker, детерминированно проверяет компилируемость. Граница доверия: всё прошедшее дальше считается «как написано», без веры в LLM.

**Мир «доказывает» (доверенный):**
5. **Solver Core (SMTChecker)** — машина-оракул. Три вердикта: `proved` / `counterexample + witness` / `inconclusive (timeout/k-bound)`. Не часть «интеллекта» — источник истины.

**Вне петли (измерение):**
6. **Ground-Truth Comparator** — сверяет сгенерированные [1]+[2] с эталонными CVL-спеками Aave (`totalSupply_EQ_sumAllBal`, ghost `rayMul`/`rayDiv`, и т.д.). Не участвует в доказательстве — даёт research-метрику «насколько агент близок к эксперту».

## 4. План фаз (порядок: сначала проверить ядро, потом агенты по одному)

Принцип: **«сначала доказать, что труба не течёт, потом наливать воду».** Каждая фаза изолирует одну переменную.

### Фаза 0 — Доверенное ядро на ручных спеках
Человек вручную пишет экономический инвариант + harness для `deposit`; прогоняем через Translator → SMTChecker.
- **Цель:** доказать, что ядро [4]+[5] вообще доказывает `deposit`, и руками нащупать, где SMTChecker упирается (арифметика, k-bound).
- **Агентов нет.** Это калибровка стены до вложений в LLM.
- **Выход:** работает ли петля в принципе + первая карта ограничений SMTChecker на ERC-4626.

### Фаза 1 — Economic Spec Generator (модуль [1])
Включаем генерацию экономического инварианта; harness по-прежнему ручной.
- **Цель:** измерить в изоляции, насколько LLM генерит корректный экономический инвариант, сверяясь с [6].
- **Выход:** метрика качества экономической спеки + проверка гипотезы «экономику генерить легко».

### Фаза 2 — Functional Harness Generator (модуль [2])
Включаем генерацию harness.
- **Цель:** найти главную предполагаемую стену — автосинтез ghost-арифметики и overflow-обвязки.
- **Выход:** где именно и как часто ломается harness; это центральный научный результат цикла.

### Фаза 3 — Замыкание петли + классификатор (модуль [3])
Полный автоматический проход: [1]→[2]→[4]→[5]→[3].
- **Цель:** критерий успеха — **цикл прошёл end-to-end хотя бы раз на `deposit`.**
- **Выход:** сквозной прогон + классификация исходов.

---

## 5. Ожидаемые выходы (что считаем результатом)

**Критерий успеха цикла:** петля прошла end-to-end хотя бы один раз на `deposit`.

Артефакты, которые цикл обязан произвести (вне зависимости от того, прошёл он или нет):

1. **Карта стен** — где ломается каждый модуль (главная ценность; отрицательный результат здесь так же ценен, как положительный).
2. **Измерение разделения слоёв** — подтвердить/опровергнуть гипотезу «экономический инвариант ≪ proof harness по сложности» количественно.
3. **Baseline аудита** — точка отсчёта, относительно которой потом измеряется синтез.
4. **Ground-truth дельта** — насколько сгенерированные спека+harness близки к эталону Aave.
5. **Решение о ядре** — подтвердить SMTChecker или зафиксировать, что упёрлись и нужен Certora/theorem-proving путь (привязка к приоритету №6 из `research_insights.md`).

**Явно НЕ ожидаем:** продукта, обобщения на другие методы/домены, высокого precision, автономности без человека.

## 6. Последствия

### Положительные
- Кратчайший путь к замыканию нейросимволической петли (минимум инфраструктуры).
- Модульность по линии доверия → можно измерять вклад каждого компонента отдельно.
- Инсайт «функциональный vs бизнес пруф» встроен в архитектуру, а не приклеен.
- Готовый ground truth (Aave CVL) → честная метрика без субъективизма.
- Любой исход информативен (карта стен ценна даже при «не прошло»).

### Отрицательные / принимаемые издержки
- SMTChecker почти наверняка упрётся в ghost-арифметику `rayMul`/`rayDiv` — но это запланированный результат, не сюрприз.
- Режим аудита НЕ проверяет наш главный дифференциатор (синтез) — отложено осознанно.
- Bounded-гарантия (k-bound): глубокие/многошаговые инварианты в этом цикле недостижимы.
- Один метод → нулевая внешняя валидность для обобщений (и не претендуем).

## 7. Риски (из `research_insights.md`, перенесены на этот цикл)

| Риск | Источник | Митигация в этом цикле |
|---|---|---|
| **Доказуемость ≠ корректность спеки** (слабый инвариант → молчаливый пропуск) | Tolmach; Agentic MC (их нерешённый failure mode) | Ground-Truth Comparator [6] сверяет с эталоном; classifier [3] помечает «слишком слабый инвариант» |
| **Стена ghost-арифметики harness** | GitHub-разбор Aave specs | Изолирована в Фазе 2; это объект измерения, не препятствие |
| **k-bound / глубокие инварианты** | Agentic MC | Принято как граница цикла; фиксируем, где упёрлись |
| **LLM деградирует на незнакомом** | Johansson | ERC-4626 — стандартизированные имена (deposit/totalSupply), благоприятный случай; не bridges |
| **Стохастичность покрытия спеки** | Johansson | Несколько прогонов генератора; меряем вариативность |

## 8. Осознанно отложено (НЕ в этом цикле)

- Синтез (`спека → код`) — наш дифференциатор, но следующий цикл.
- Другие методы (`mint`/`withdraw`/`redeem`), композиция, cross-contract, liveness.
- Само-наполняемая библиотека спек / proof harness (приоритет из артефакта).
- Замена/выбор ядра под глубокие инварианты (Certora, theorem proving) — решение по итогам Фазы 0/2.
- Полная автоматизация классификатора и refinement-цикл (CEGAR на уровне спек).
