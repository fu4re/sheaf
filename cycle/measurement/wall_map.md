# Карта стен SMTChecker — экспонат #1 (T-04: ghost-абстракция арифметики)

**Вопрос (T-04 / риск №2):** экономический инвариант `deposit` доказуем в SMTChecker?
В SMTChecker нет CVL-ghost'ов и storage-hooks — выразима ли вообще ghost-абстракция
нелинейной арифметики, и снимает ли она стену?

**Дата:** 2026-06-21 · solc 0.8.35 · z3 4.16.0 · движок CHC · targets=assert

---

## Матрица экспериментов

Инвариант во всех прогонах один: **`totalShares <= totalAssets`** (солвентность,
цена доли ≥ 1 — каждая доля обеспечена ≥ 1 ед. актива). Меняется только то, как
обрабатывается операция `shares = floor(assets * totalShares / totalAssets)`.

| # | Harness | Арифметика доли | Вердикт ядра |
|---|---|---|---|
| **A** | concrete (subclass) | реальная `assets * totalShares / totalAssets` (нелинейная) | **`inconclusive`** — `could not be proved` |
| **B** | ghost (frozen axiom) | havoc'нутая доля + `require(mintedShares <= assets)` | **`proved`** |
| **B-buggy** | ghost (ослабл. аксиома) | `require(mintedShares <= assets + 1)` | **`counterexample`** (`deposit(1,1); deposit(0,1)` → shares=2 > assets=1) |

Те же два режима — через весь пайплайн [1]→[4]→[5]→[6] на одном инваринте агента:
`subclass` → `inconclusive`; `ghost` → `proved`. **Стена в proof harness (арифметике),
не в инварианте** — количественное подтверждение гипотезы ADR §5.2.

---

## Находки

1. **Нелинейное умножение двух storage-переменных — реальная стена.** CHC не
   доказывает `totalShares <= totalAssets` на концентрате: вывод `floor(a·s/A) <= a`
   из `s <= A` требует рассуждения о произведении — солвер сдаётся (`could not be proved`).

2. **Ghost-абстракция ВЫРАЗИМА в SMTChecker без CVL-hooks.** Механизм:
   - **havoc** = доля становится недетерминированным **входом функции** (`mintedShares`),
     SMTChecker перебирает все значения;
   - **аксиома** = `require(...)` действует как `assume`, ограничивая havoc;
   - инвариант доказывается **относительно аксиомы**, произведение не вычисляется.

   Это и есть «опереться на уже доказанную аксиому из другого уровня математики»,
   реализованное штатными средствами Solidity. Заменяет CVL `ghost` + `axiom`.

3. **Абстракция не вакуумна.** Слишком слабая аксиома (`<= assets+1`) не даёт ложного
   `proved` — ядро находит контрпример. Неверная по слабости аксиома безопасна.

---

## Границы находки (честные оговорки)

- **Использована ЛИНЕЙНАЯ над-аппроксимация** (`mintedShares <= assets`), достаточная
  именно для солвентности при цене ≥ 1. Снимает ли SMTChecker **тугие НЕЛИНЕЙНЫЕ**
  аксиомы (round-down bound `mintedShares*totalAssets <= assets*totalShares` + tightness)
  для более тонких свойств — **ещё открыто**, следующий экспонат карты.
- **Соундность аксиомы доказывается ОФФЛАЙН**, не ядром. `proved` означает «верно при
  условии, что ghost-аксиома — добросовестная абстракция». Слишком СИЛЬНАЯ (несоундная)
  аксиома дала бы ЛОЖНЫЙ `proved` — это и есть риск «доказуемость ≠ корректность» и
  причина, по которой ghost-библиотека должна **курироваться** (moat = курирование,
  insights приоритет №1).
- Свойство bounded по природе вызовов (CHC-инвариант), но многошаговые/накопительные
  атаки глубже k не покрыты (риск k-bound остаётся, §7 ADR).

## Вход для решения §5.5 (о ядре)

SMTChecker **проходит первую стену арифметики** при ручной ghost-обвязке — путь
SMTChecker подтверждён для Tier-1.5. Открытый порог: тугие нелинейные аксиомы и
реальный Aave `rayMul`/`rayDiv` (Tier-2, T-14). Пока **не** требуется уходить на
Certora/theorem-proving; пересмотр — после Tier-2.

`trusted/harness/ProportionalVaultGhost.sol` (+ `…Buggy.sol`),
