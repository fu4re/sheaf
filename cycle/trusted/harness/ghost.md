# Trusted harness — frozen ghost-arithmetic library

**Trust line:** TRUSTED. Everything here is PRE-FIXED and human-curated. It is
NOT generated by the agent. The agent proposes the 1-line economic invariant;
this library supplies the scaffolding that lets the solver discharge it.

This is the "rely on already-proven axioms from another level of mathematics"
principle: a nonlinear machine operation (`a * b`, `mulDiv`) is intractable for
the SMT solver, so we hide it behind a ghost function whose behaviour is fixed by
a small set of axioms, and prove the invariant *relative to those axioms*.

## Slice 1 (current) — overflow обвязка only

The only trusted scaffolding exercised so far is the overflow guard inside the
mocked vault (`require(... <= type(uint128).max)`). Arithmetic is linear (1:1),
so no ghost abstraction is needed yet. This slice isolates the trust-line
*separation* mechanics; it does not yet hit the nonlinear wall.

## Slice 2 (RESOLVED, T-04) — ghost abstraction of `mulDiv`

When the vault computes `shares = assets * totalShares / totalAssets`, the
product of two state variables is nonlinear → the CHC engine cannot reason about
it (confirmed: concrete vault → `could not be proved`). See the full exhibit in
[`../../measurement/wall_map.md`](../../measurement/wall_map.md).

**Mechanism that works (no CVL hooks needed):**
- the ghost result becomes a **havoc'd function input** `mintedShares` (SMTChecker
  explores all values);
- the axiom is a **`require(...)`** acting as `assume`, pinning the havoc;
- the invariant is proved RELATIVE to the axiom, never touching the product.

Implemented in [`ProportionalVaultGhost.sol`](ProportionalVaultGhost.sol).

**Frozen axiom used (Slice 2):** under solvency (`totalShares <= totalAssets`,
price ≥ 1), `floor(assets * totalShares / totalAssets) <= assets`. A LINEAR
upper bound — sufficient for the solvency invariant, and the solver can use it
directly. Result: **`proved`**.

**Still open (next exhibit):** tight NONLINEAR axioms for finer properties —

1. round-down bound:        `ghostMulDiv(a,b,c) * c <= a * b`
2. tightness (no slack):    `a * b < (ghostMulDiv(a,b,c) + 1) * c`

— whether SMTChecker can *use* these (they contain products) is untested. And
real Aave `rayMul`/`rayDiv` (Tier-2, T-14).

**Soundness note:** the axiom's faithfulness is justified OFFLINE, not by the
solver. A too-weak axiom merely fails to prove (safe — see `…GhostBuggy.sol`); a
too-STRONG/unsound axiom would falsely prove. Hence the ghost library must be
curated (moat = curation).
