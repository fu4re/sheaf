## 1. Вердикты T1 (эксперимент, стенд kontrol 1.0.255 / K v7.1.337 / KEVM 1.0.678)

| **Q1** инкремент | **только правка, N=2 правила** (`#mkCall`+`#mkCreate`), diff=3 аддитивные строки, покрывает все 6 CALL-опкодов; регрессия зелёная | наивная оценка «6 опкодов» → реальная «2 внутренних стыка»; путь (i) неинвазивный хук провалился (самоприменение, переусчёт) |

## 2. Вердикты T2 (теория, формулы над KEVM-конфигурацией)

- **Интерфейсы** deposit / withdraw_V / withdraw_F: `(Pre, Post, Exit, Foot_r, Foot_w, Rely, Guar)` выписаны в псевдо-K, транслируемом в claims. Ключевое поле — **Rely в точке приостановки** (H8): V2 (CALL до списания) для V, F3 (CALL после списания) для F.
- **Self-compat (risk №1) снят редукцией:** Guar/Rely — отношения на переходах, не свойства экземпляров → индексация по callDepth устраняется, self-compat = `Guar_w ⟹ Rely_w`. V: `Guar_w^V ⟹ ¬Rely_w^V` (внутренний фрейм уменьшает bal[U], Rely требовал сохранения) — **FAIL, как и должно**. F: `Rely_w^F @ F3 = ⊤` над bal[U] (уже списано) — **PASS**.
- **Дискриминатор (§4.5):** временнáя привязка точки записи к точке приостановки; локальная перестановка операторов переворачивает Guar, Rely и self-compat.
- **Guar_env (risk №2):** над-аппроксимирующее символьное `[trusted]`-правило (KEVM idiom); таблица из 7 «может» + 6 «не может», каждое с обоснованием из семантики EVM.
- **`<inFunc>`-монитор:** `callCounter` недостаточен (реентранси-предикат стеко-подобен) → постулирован `<inFunc> : Map(sig ↦ активных фреймов)`, `reentered(sig) ≜ <inFunc>[sig] ≥ 2`. Реализация — прекондиция T3 (см. К4).
- **Таблица obligations (§6.2):** 11 строк; 3 первичных различителя V/F (#3, #6, #8) + производные #10, #11.

## 3. Центральная лемма A3b (принята как есть)

Ход self-compat из T2 §4.1 оформляется в A3b как **отдельная лемма формализма над EVM**:

> **Лемма (Reentrancy-as-self-interference).** Для loop w с интерфейсом `(…, Rely_w, Guar_w)`, где Rely/Guar — отношения на переходах конфигурации: глобальная устойчивость trace-инварианта w при произвольном ре-входе окружения эквивалентна `Guar_w ⟹ Rely_w` (self-compat). Индексация по экземплярам фрейма устранима (Jones-style relation on ⟨γ, γ′⟩); ре-вход наблюдаем через `<inFunc>` в точках приостановки (H8).

Новизна — применение R/G-редукции к реентранси над EVM-байткодом (P1.5: прецедента нет). Для A3b это несущий факт, не вспомогательный.

## 4. Корректировки приёмки (К1–К4)

**К1 — Rely-зависимость дискриминатора #3 [директива T3].**
FAIL на #3 для V — артефакт строгой Rely_w^V (`bal[U] = B₀` заморожен). При ослаблении до «запрет уменьшения» (`bal[U] ≥ B₀` на интервале приостановки) #3 → PASS, а #6/#8 продолжают падать (внутренний withdraw *уменьшает*). **Решение:** ослабленная Rely_w^V — основная редакция; строгая — вторичный контроль. Робастные дискриминаторы — **#6 и #8**, не #3. T3 прогоняет обе редакции; клейм дискриминации опирается на ослабленную, иначе различение V/F рискует быть артефактом переограничения.

**К2 — A_selfdestruct снят.**
Корневой INV сформулирован как `balances[C] ≥ Σ bal[u]` (неравенство). SELFDESTRUCT/SENDALL в адрес C только усиливает неравенство → допущение избыточно. Убрано из леджера; остаётся range-wellformedness в Rely.

**К3 — Guar_env: provenance-клауза — главный кандидат на невыразимость [директива T3].**
Клауза «S′[C] изменён только через легитимные SSTORE фреймов C, отражённые в счётчиках» — темпоральное/provenance-условие, спрессованное в state-relation; в K-`requires`, вероятно, не кодируется. **Рекомендованная форма** (и будущая форма PAR-индукции): декомпозиция по H8 — `env-step` покрывает только сегменты **без активных C-фреймов** (там `S[C]` неизменен тривиально, `balances[C]` меняется только прямым переводом), ре-входы моделируются **инстанциацией наших loop-claims**, не внутри env-step. Цепочка: `env-step* ; C-claim ; env-step* ; …` — provenance-клауза исчезает. T3 пробует декомпозированную форму первой; монолитный env-step — в журнал зазоров, если декомпозиция не пройдёт.

**К4 — реализация `<inFunc>` дешевле §2.**
Вместо инструментации «входа в функцию» (JUMPDEST/диспетчер — Solidity-специфично, не bytecode-clean): инкремент на **существующем стыке `#mkCall`** с предикатом `callee == C`, ключ = `callData[0..4]` создаваемого фрейма; декремент на 3 exit-стыках (чтение `<callData>` завершаемого фрейма до pop). Остаётся в классе «аддитивные правки на стыках» T1, обходит §7.1, формулы T2 не меняет. Отступной путь (если pop не даёт прочитать селектор) — JUMPDEST.

**Мелкое:** критерий §6.4 T2 инвертирован; правильная форма беззубости — *ни одна* obligation не различает V/F. Таблица верна.
