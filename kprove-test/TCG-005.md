## 2. Вердикты ARL-чтения (первоисточник, LMCS 15(2:5) 2019)

1. **Секвент:** `S, A ⊢_C φ ⇒∀ φ′`. A — аксиомы (all-path правила, «can be assumed valid»), C — circularities («postulated but not yet justified»), применимы через Axiom только после переноса C→A правилом Transitivity; Reflexivity требует C=∅.
2. **Theorem 7.1 (Soundness) сформулирована только для пустых A/C.** Общий случай — **Lemma 7.2**: `S, A ⊢_C φ⇒∀φ′` ⟹ (∀n: `S ⊨⁺ₙ A` и `S ⊨⁺ₙ₋₁ C` ⟹ `S ⊨*ₙ φ⇒∀φ′`, и `S ⊨⁺ₙ` при C≠∅). **Цитировать Lemma 7.2.**
3. **Side-condition:** гипотеза о A/C — **⊨⁺** (валидность + прогресс: постусловие достигается после ≥1 шага на всех полных путях), строже простой валидности.
4. **Индекс n−1 у C — формализованный step-guard.** Цитируемое обоснование: «This would obviously be unsound if the new assumption was available immediately» (§4).
5. **Полные пути:** Def 3.1/3.2 — complete = максимальный конечный путь; бесконечные исключены из квантификации (partial correctness).
6. **Coq-механизация** заявлена для soundness; покрытие непустых A/C — интерпретация, не текст. Не заявлять без проверки Coq-разработки.

## 3. Сведение эксперимент ↔ теория (главный результат пары отчётов)

Наблюдение C9-Q1 (trusted применим только после шага, не передоказывается) — это **в точности механика Lemma 7.2 с trusted ∈ C**: индекс `n−1` = step-guard. Эксперимент и статья описывают один механизм с двух сторон. Следствия:

- **Противоречие документации разрешено в пользу манула:** «trusted = proven circularities» — точное описание поведения kprove v7.1.337; issue #1277 — нереализованный design intent. Цитировать оба с ролями (манул — behavior, issue — intent). Решение TCG-004 «манул не цитировать» отменено.
- **Собственная лемма (Step-Guard Absorption, обсуждалась при приёмке C9) не нужна:** шаг индукции — прямая инстанциация Lemma 7.2 с A=∅, C=T(h).
- **Прогресс самоподдерживается по DAG:** узел, доказанный с C≠∅, по заключению Lemma 7.2 сам ⊨⁺-валиден → годится в trusted для родителя без дополнительной работы.
- **Формулировка для paper:** «наблюдаемое поведение kprove согласуется с механикой Lemma 7.2» — НЕ «kprove реализует Lemma 7.2» (это интерпретация двух отчётов, не заявление RV).

## 5. Теорема A3a — финальная редакция

**Посылки:**
- **(H1)** Бандл структурно валиден; рёбра типизированы: подграф **trusted-lemma** ацикличен и замкнут; **consequence**-рёбра ведут только в junction/subsumption-узлы; roots достижимы. (Шаги 1–4 протокола + проверка типизации.)
- **(H2)** Каждый claim — all-path reachability claim с **явным** атрибутом.
- **(H3′)** Для каждого узла h зафиксирован Accept kprove, где claims детей по trusted-lemma-рёбрам подключены как trusted — применяются как **step-guarded circularities**, не передоказываются (поведение верифицировано: kprove v7.1.337, report.md Q1).
- **(H4)** Assumptions 1, 2, 4, 6 whitepaper; A_keccak (при дизъюнктности слотов); **S weakly well-defined** (Def 3.1 ARL).
- **(H5)** Каждый узел-цель trusted-lemma-ребра **⊨⁺-валиден**; нуль-шаговые узлы — цели только consequence-рёбер (механическая проверка шага 4).

**Заключение:** каждый root-claim валиден: `S ⊨ φ_r` (узлы с C≠∅ — `S ⊨⁺`); по Assumptions 1–2 переносится на →EVM. На EVM квантификация полная (газ-микролемма).

**Доказательство (схема):** индукция по топологическому порядку trusted-lemma-подграфа. База: листья (goal-as-own-circularity ⟹ C≠∅ ⟹ ⊨⁺ по Lemma 7.2). Шаг: узел h — инстанциация **Lemma 7.2** с A=∅, C=T(h): из `S ⊨⁺ T(h)` (IH) следует `S ⊨* φₕ`, и `S ⊨⁺ φₕ` при C≠∅. Junction-узлы участвуют через Consequence — им достаточно ⊨*. IH формулируется как **S-валидность** детей (семантическая), не выводимость.

**Статус:** все посылки подтверждены (статья + эксперимент). Осталось: написать доказательство + две аппендикс-проверки (§6).

## 6. Остаточные проверки (дешёвые, не блокируют написание)

1. **Goal-as-own-circularity:** регистрирует ли kprove цель как собственную circularity (⟹ C≠∅ у листьев ⟹ ⊨⁺ бесплатно). Один прогон на стенде C9. До проверки H5 у листьев разряжается семантическим аргументом (слабее, не механический).
2. **Consequence-механика на стенде:** junction как импликация внутри родительской спеки (не как trusted-лемма) — показать на kprove-примере.
3. **Booster-подтверждение Q1** (заявлено «ожидается идентично», не наблюдалось).
4. **Coq-разработка ARL:** покрывает ли механизация непустые A/C (влияет только на формулировку в paper).
5. **Ghost-инкремент на CALL:** механика update-правил не продемонстрирована (показаны декларация + констрейн); если потребует правки opcode-правил — форк растёт с 1 строки, A5 дорожает. → C7-остаток.
6. **CSE SMT sort-крэш** (`Sorts SortAccount and Int are incompatible` на `--cse` пути setUp) — баг-репорт RV; fallback-исполнение не наблюдалось (вердикт Q3 держится на guard'е по построению).
