## 1. Объект и определения

### 1.1 Семантики и отношение переходов

- **S** — vendored KEVM 1.0.678; **S′** = S + `ghost.diff`.
- Правила K-теории делятся на **transition-правила** (перезапись конфигурации) и **`[function]`-правила** (уравнения над function-символами; в Kore компилируются в equational axioms и применяются бэкендом при упрощении терма, шагов перехода не образуют). Это конвенция семантики K; её поведенческое подтверждение на пиннованном стенде — **VO-K** (§8). *(Фикс R2-High-1: v2 опиралась на конвенцию молча.)*
- **Конфигурации.** Cfg(S), Cfg(S′) — термы единственного top-cell `<kevm>`, рассматриваемые modulo эквациональной теории function-символов. Пишем **NF(t)** для множества/класса функционально-нормализованных представителей `t`: на ground-термах обычно singleton; на символических термах может быть конечным guard-разбиением. Нормализация GF на wf-домене корректна в смысле Л-GF/NF.
- **Отношение переходов.** c → d :⟺ c ⇒_t u по одному transition-правилу t и d ∈ NF(u). Так определены и →_S, и →_S′. GF-уравнения растворяются в NF и **не порождают transition-шагов**; возможное symbolic branch-splitting от GF живёт только в ghost-RHS и стирается π (Л-GF/NF, Л3′).

### 1.2 Содержимое diff-а (дословно; хунки пронумерованы как в §7)

- **Три ghost-ячейки** в `<kevm>`, **вне `<ethereum>`**: `<callCounter> 0 </callCounter>` (Int), `<inFunc> .Map </inFunc>` (**Map**: 4-байтовый селектор → число активных C-фреймов), `<monitoredAddr> 0 </monitoredAddr>` (Int).
- **Три функции** `#selKey(Bytes)`, `#ifGet(Map,Int)`, `#bump(Map,Int,Int,Int,Int)` — `[function, total]`, в LHS правил не появляются.
- **Inline-расширения пяти transition-правил:** `#mkCall` (инкремент `<callCounter>`; `<inFunc> IF => #bump(IF, ACCTTO, MADDR, #selKey(ARGS), 1)`; read-only `<monitoredAddr> MADDR`), `return.exception/revert/success` (read-only `<id> CID`, `<callData> CALLDATA`, `<monitoredAddr> MADDR`; `<inFunc> => #bump(IF, CID, MADDR, #selKey(CALLDATA), -1)`), `#mkCreate` (только `<callCounter>`).

Ключевой факт формы: **diff не вводит ни новых конструкторов `<k>`, ни новых transition-правил.** Все семантические изменения — inline-эффекты в RHS существующих transition-правил плюс уравнения-хелперы.

### 1.3 Ghost-синтаксис, проекция, well-formedness

**Ghost-ячейки:** GC = {`<callCounter>`, `<inFunc>`, `<monitoredAddr>`}. **Ghost-функции:** GF = {`#selKey`, `#ifGet`, `#bump`} — встречаются только внутри RHS-обновлений GC-ячеек. Ghost-элементов `<k>` нет (D3 = ∅).

**Проекция π : Cfg(S′) → Cfg(S)** — стирание трёх GC-ячеек. π тотальна; π(c′) ∈ Cfg(S), т.к. diff добавляет GC на верхнем уровне `<kevm>` (хунк 1), не меняя прочие ячейки; нормализованность сохраняется (стирание не вводит function-символов).

**Well-formedness.** *(Фикс R2-High-2.)*

> **Cfg_wf(S′)** := {c′ ∈ Cfg(S′) | `<callCounter>`, `<monitoredAddr>` — значения сорта Int; **range(`<inFunc>`) ⊆ Int**}.

Первые два условия даёт сортовая дисциплина ячеек; третье — **семантический инвариант**: сорт Map в K не ограничивает значения, и `{M[K]}:>Int` в `#ifGet` на map-е с не-Int значением — застрявший каст. Следствие: атрибут `[total]` у `#ifGet` в строгом смысле держится **только на wf-домене** (VO-GF/NF переписан, §8).

## 2. Формулировка

### Лемма A5 (прозрачность инструментации; сильная форма над wf-доменом)

Для S′ = S + `ghost.diff`, при обязательствах §8:

**(A5-0, замкнутость)** Cfg_wf(S′) замкнут относительно →_S′, и все init-конфигурации S′ лежат в Cfg_wf(S′).

**(A5-бисимуляция)** Отношение **R = {(c′, π(c′)) | c′ ∈ Cfg_wf(S′)}** — сильная бисимуляция между (Cfg_wf(S′), →_S′) и (Cfg(S), →_S):

- **(A5-fwd)** если c′ →_S′ d′, то π(c′) →_S π(d′) (и d′ ∈ Cfg_wf по A5-0);
- **(A5-bwd)** если π(c′) →_S d, то существует d′ ∈ Cfg_wf(S′): c′ →_S′ d′ и π(d′) = d;
- **(A5-stuck)** c′ ∈ Cfg_wf — тупик S′ ⟺ π(c′) — тупик S.

**(A5-lift, сюръективность)** для всякого c ∈ Cfg(S) и всякого wf ghost-состояния g прообраз c′ = c ⊕ g ∈ Cfg_wf(S′) существует и π(c′) = c — стартовые конфигурации claims поднимаются.

Шаг-в-шаг, без τ-класса: длины путей совпадают, полные пути соответствуют побиективно на уровне не-ghost наблюдений.

**Следствие (перенос claims):** для всякого all-path claim `φ ⇒∀ φ′` над не-ghost паттернами: `S ⊨ φ ⇒∀ φ′ ⟺ S′ ⊨ φ^ ⇒∀ φ′^`, где `^` добавляет GC-материю **только свежими, попарно независимыми переменными в Pre и Post**, причём в Pre — **под wf-констрейнтом** (§5, C1).

**Замечание о сужении домена.** Ограничение wf не сужает предмет: конкретные исполнения стартуют из init ∈ Cfg_wf и не покидают его (A5-0); символьные claims обязаны констрейнить ghost-переменные wf-предикатом (C1/C6) — ill-formed ghost-состояния не соответствуют ни одному исполнению S′ и носителями смысла не являются.

## 3. Вспомогательные леммы

### Л-GF/NF (ghost-функции и нормализация на wf-домене)

**Утверждение.** На аргументах, у которых Map-параметр well-formed (range ⊆ Int), GF-нормализация корректна: `#selKey`, `#ifGet`, `#bump` имеют полное guard-разбиение; на ground-аргументах результат однозначен, на символических аргументах NF может быть конечным множеством guarded-ветвей. `#bump` возвращает well-formed Map во всех ветвях. Кроме того, π коммутирует с GF-нормализацией, потому что все GF-вхождения, введённые diff-ом, находятся внутри RHS-обновлений стираемых GC-ячеек.

**Доказательство (по тексту diff-а).**
- `#ifGet(M,K)`, M wf: ветви `K in_keys(M)` / `notBool in_keys(M)` — полное дизъюнктное покрытие; в первой ветви `{M[K]}:>Int` разрешается, т.к. M[K] ∈ Int по wf. Если guard символически не решён, NF представляется двумя guarded-ветвями. **На произвольном Map тотальность не утверждается** *(фикс R2-High-2: v2 заявляла безусловную тотальность — неверно для каста).*
- `#bump(M,A,MON,SIG,D)`, M wf: ветви `==Int` / `=/=Int` — полное дизъюнктное покрытие; при символическом равенстве NF может содержать две guarded-ветви. Результат в каждой ветви — M либо `M[SIG <- #ifGet(M,SIG) +Int D]`, где записанное значение — Int ⟹ результат wf. **Сохранение wf — несущая часть A5-0.**
- `#selKey(ARGS)`: единственное безусловное правило; тотальность сводится к стоковым `#asWord`, `#range` — VO-GF/NF.

GF встречаются в `ghost.diff` только в добавленных RHS-обновлениях `<inFunc>`; после π вся эта материя стирается. Поэтому для любого `u`, полученного D2-шагом, π[NF(u)] зависит только от не-ghost RHS стокового правила и не зависит от выбора GF-ветви. ∎

Следствие: ghost-RHS каждого D2-правила на Cfg_wf корректно нормализуется modulo GF; возможные symbolic branches различаются только в GC-части и имеют одинаковую π-проекцию.

### Л0 (замкнутость wf — доказательство A5-0)

**Утверждение.** c′ ∈ Cfg_wf(S′), c′ →_S′ d′ ⟹ d′ ∈ Cfg_wf(S′); init ∈ Cfg_wf.

**Доказательство.** Init: `0`, `.Map`, `0` — wf (хунк 1). Шаг: D1-правила GC не читают и не пишут (Л1) — ghost-часть d′ = ghost-часть c′, wf сохраняется. D2-правила пишут: в `<callCounter>` — `CC +Int 1` (Int); в `<inFunc>` — `#bump(...)`, wf-сохраняющий по Л-GF/NF; `<monitoredAddr>` не пишется никем (единственные вхождения — read-only биндинги, факт diff-а). Других писателей GC нет (полный перебор хунков, §7). ∎

Single-writer-структура: `<inFunc>` пишет только `#bump` из D2-хунков 6–9; `<callCounter>` — только инкременты хунков 5, 10; `<monitoredAddr>` — никто. Инвариант локален diff-у и переживает D1 целиком.

### Л1 (штатные правила не видят ghost)

**Утверждение.** Ни одно D1-правило не читает и не пишет GC; для D1-правила r: r применимо к c′ ⟺ r применимо к π(c′), результаты связаны π, ghost-часть неизменна.

**Доказательство.** GC введены diff-ом ⟹ отсутствуют в стоковой сигнатуре; D1-правила дословно стоковые. «Оптовый» канал закрыт размещением: снапшот/рестор мира (`#pushWorldState`/`#popWorldState`/`#dropWorldState`) переписывают поддерево `<ethereum>`/`<interimStates>`; GC — **вне `<ethereum>`** (хунк 1) ⟹ bulk-перезапись их не затрагивает (тот же механизм, которым `<callCounter>` переживает revert, T1-Q2b). Матчинг LHS(r) — только над не-ghost материей, сохраняемой π дословно; нормализация после шага не затрагивает ghost-часть (в ней нет невычисленных символов — c′ нормализована). ∎

*Опора:* дословный diff + t1_report §Q1 + регрессия (TCG-006 §1). Парсерное подтверждение по всему дереву форка — VO-2p.

### Л3′ (D2-правила проецируются на свои S-оригиналы)

**Утверждение.** Для каждого D2-правила r′ с оригиналом r и c′ ∈ Cfg_wf: (i) r′ применимо к c′ ⟺ r применимо к π(c′); (ii) образ множества нормализованных результатов r′ под π совпадает с множеством нормализованных результатов r.

**Доказательство.** Дельта r′ против r (дословный diff):
1. **RHS-обновления GC** (`<callCounter> CC => CC +Int 1`; `<inFunc> IF => #bump(...)`) — π стирает; корректность GF-нормализации — Л-GF/NF **(здесь и используется wf: матч `CC:Int` и разрешение каста гарантированы только на Cfg_wf)**; возможные GF-ветви различают только стираемую ghost-часть;
2. **read-only биндинги GC** (`<monitoredAddr> MADDR`) — свежая переменная; матч безусловен на wf-домене (значение — Int);
3. **read-only биндинги не-ghost ячеек свежими переменными** (`<id> CID`, `<callData> CALLDATA`) — ячейки присутствуют в каждой well-formed KEVM-конфигурации (статическая конфигурация K), переменные свежие, не констрейнятся ⟹ применимость не сужена; поведение configuration abstraction при добавлении cell-ссылок — G-2′/VO-6p;
4. **`requires`-дельта = ∅; не-ghost RHS-дельта = ∅** — факт diff-а (`ACCTTO`, `ARGS` уже связаны стоковым правилом: `<id> _ => ACCTTO`, `<callData> _ => ARGS`).

(i): не-ghost матч совпадает с r (п.3–4); ghost-матч безусловен (п.2 + сорта wf). (ii): не-ghost RHS дословно r; ghost-дельта нормализуется modulo GF и стирается π; нормализация не-ghost части идентична в обоих правилах (общие термы). Поэтому каждая нормализованная ветвь r′ проецируется в нормализованную ветвь r, и наоборот любая ветвь r поднимается произвольной wf ghost-ветвью r′. ∎

### Л4′ (характеризация допустимых эффектов)

**Утверждение.** Diff (а) не пишет ни в одну не-ghost ячейку (включая `<gas>`); (б) не сужает применимость ни одного transition-правила — гарды инструментации живут внутри GF-уравнений, не в `requires`; чтение не-ghost материи допустимо и безвредно.

**Доказательство.** (а) — перебор хунков: все добавленные `=>` — только `<callCounter>`, `<inFunc>`; добавленные `<id>`, `<callData>`, `<monitoredAddr>` — без стрелки. (б) — `requires` не добавлен ни к одному стоковому правилу (факт diff-а); guard `callee==C` — ветвление тотального-на-wf `#bump` (комментарий K4 в diff-е). Газ: ghost-обновления не читают и не пишут `<gas>`; шагов diff не добавляет (GF — уравнения) ⟹ газ-микролемма A3a переносится на S′ дословно, длины путей совпадают точно. ∎

## 4. Доказательство леммы A5

**(A5-0).** Л0. ∎

**(A5-fwd).** c′ ∈ Cfg_wf, c′ →_S′ d′ по transition-правилу r′. r′ ∈ D1 — Л1. r′ ∈ D2 — Л3′(ii): π(c′) →_S π(d′) по оригиналу r. Других transition-классов нет (GF — уравнения, §1.1; D3 = ∅). d′ ∈ Cfg_wf — A5-0. ∎

**(A5-bwd).** π(c′) →_S d по r ∈ S. Если r ∈ D1 — по Л1 r применим к c′ (матч не зависит от ghost), результат проецируется в d, ghost-часть неизменна ⟹ wf. Если r — оригинал D2-правила r′ — по Л3′(i) r′ применим к c′ **при любом wf ghost-состоянии** (безусловные ghost-матчи на wf-домене + Л-GF/NF), π(результата) = d, результат wf по A5-0. Ровно один шаг. ∎

**(A5-stuck).** Множества применимых transition-правил у c′ ∈ Cfg_wf и π(c′) совпадают с точностью до биекции r ↔ r′ (Л1, Л3′(i)) ⟹ тупики совпадают. Новых тупиков S′ на wf-домене не вводит: единственный кандидат — застревание нормализации ghost-части — исключён Л-GF/NF на Cfg_wf. Вне wf-домена лемма ничего не утверждает (и не обязана — Замечание §2). ∎

**(A5-lift).** c ⊕ g: приписывание трёх GC-ячеек с wf-значениями g к нормализованной c даёт нормализованную конфигурацию S′ (структура прочих ячеек не меняется; GC-значения — значения, не редексы); π(c ⊕ g) = c по определению π. ∎

**Детерминизм:** биекция применимых transition-правил ⟹ степень transition-недетерминизма в каждой wf-конфигурации идентична. Символические GF-ветви могут размножать только представление ghost-части; все их π-образы совпадают, так что не-ghost nondeterminism не расширяется. ∎

## 5. Что переносится (следствия)

### C1 — claims без ghost

`S ⊨ φ ⇒∀ φ′ ⟺ S′ ⊨ φ^ ⇒∀ φ′^` при условиях:
- GC-материя входит в φ^ и φ′^ только **свежими, попарно независимыми между Pre и Post переменными** (либо ячейки опущены — K доукомплектует);
- в **Pre (φ^)** ghost-переменные дополнительно **констрейнены wf-предикатом**: для `<callCounter>`, `<monitoredAddr>` достаточно сорта Int; для `<inFunc>` — явный предикат `wfMap(M)` := «range(M) ⊆ Int» (канонической форме claims — требование C6);
- в **Post (φ′^)** ghost-переменные свободны без констрейнтов (wf в Post даром по A5-0, констрейнт не нужен и, будучи чужим, мог бы блокировать матч).

Направления:
- (S⊨ → S′⊨): полный S′-путь из φ^ стартует в Cfg_wf (wf-констрейнт Pre) ⟹ лежит в Cfg_wf (A5-0) ⟹ проецируется (A5-fwd) в полный S-путь из φ; тот достигает φ′; прообразная конфигурация удовлетворяет φ′^ — ghost-переменные Post свободны, никакое ghost-значение не блокирует матч.
- (S′⊨ → S⊨): полный S-путь из φ поднимается: старт — A5-lift с любым wf ghost-состоянием, разрешённым φ^ (свободные wf-констрейненные переменные разрешают все wf-значения, в частности init); шаги — A5-bwd индукцией; полнота и длины — A5-stuck + шаг-в-шаг.

**Ill-formed ghost-стартов направление (⟹) не требует:** претензия S′⊨ φ^⇒∀φ′^ квантифицирует по конфигурациям, удовлетворяющим φ^, а φ^ несёт wf-констрейнт. *(Фикс R2-High-2 в следствии: без wf-констрейнта в Pre эквивалентность недоказуема — свежая Map-переменная пробегала бы ill-formed map-ы, на которых S′-поведение не определено леммой.)*

### C2 — claims с ghost в Pre/Post (форма A3b)

Не-ghost проекция такого claim-а — свойство S (A5-fwd/bwd). Ghost-часть — свойство только S′; её связь с EVM-реальностью даёт не A5, а адекватность монитора (§6). Требование wf на ghost-паттерны Pre распространяется и на эти claims (C6).

### C3 — композиция с Assumption 1

Assumption 1 (S ≈ →EVM) + A5 ⟹ S′ ≈ →EVM на не-ghost наблюдаемых, для wf-траекторий — т.е. всех траекторий из init и всех wf-констрейненных символьных стартов. Vendored fork законно замещает vendored KEVM; `ghost.diff` + данный документ + VO-протокол — часть сертификата.

### C4 — регрессия

Зелёная регрессия форка — выборочное свидетельство (A5-fwd); носитель доверия — доказательство + VO.

## 6. Границы

1. **Адекватность ghost-значений не утверждается.** «`#ifGet(<inFunc>, sig) ≥ 2` ⟺ реентранси по sig» (INV_inFunc) — отдельное свойство; A5 держится и при phantom-return-переусчёте (TCG-007 §4.1). A3b несёт INV_inFunc отдельной посылкой (мини-экземпляр: в-спеке; общий случай: C11).
2. **`#mkCreate` не обновляет `<inFunc>`** — create-фрейм C монитором не отслеживается. Для A5 нерелевантно; граница адекватности INV_inFunc, наследуемая A3b.
3. **A5 привязана к данному diff-у.** Эволюция (C11) — повторный проход VO; при появлении ghost-элементов `<k>` — обобщённая форма (Приложение A).
4. **Kontrol-обвязка вне предмета.**
5. **Wf-домен** *(новая, R2)*: вне Cfg_wf лемма молчит; это не сужение предмета (Замечание §2), но каноническая форма claims **обязана** нести wf-констрейнт на ghost-паттерны Pre — иначе следствия C1/C2 неприменимы. Уходит требованием в C6.

## Приложение A. Обобщённая (слабая) форма — на случай эволюции diff-а

Если будущий патч (напр., C11) введёт ghost-элементы в `<k>` (D3 ≠ ∅), действует слабая (stuttering) бисимуляция со следующими параметрами:

- π дополнительно стирает ghost-элементы из `<k>`;
- (A5-bwd): **τ\***-шагов до применимости; конечность τ-серии — из несамопорождения (VO-4);
- Л2 (немость, тотальность, терминируемость, детерминизм D3) — с VO-3/4/5; тотальность D3 — на wf-домене (урок R2-High-2);
- Л3′/Л4′ — в редакции v2/v3; Cfg_wf и A5-0 — обязательны и в слабой форме (D3-правила добавляются в single-writer-перебор Л0);
- C1 — с двусторонней свежестью ghost-переменных и wf-констрейнтом Pre;
- определение → — то же (§1.1): D3-шаги — transition-шаги (τ-класс), GF — уравнения.
