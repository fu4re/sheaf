## Q0 — `<inFunc>` реализация (прекондиция)

**Вердикт:** `реализовано (путь: #mkCall) · diff = 44 аддитивные строки (~22 семантических K) ·
PROVED reentered@depth2 · JUMPDEST fallback НЕ потребовался`.

### Разведка: читается ли селектор на exit до pop (гейтящий вопрос К4)

`#popCallStack` (evm.md:252) восстанавливает **весь** `<callState>` из стека, а `<callData>` —
его ребёнок (evm.md:67). Три правила выхода фрейма `#return.exception` / `#return.revert` /
`#return.success` (evm.md:1826/1834/1844) переписываются **в** `#popCallStack ~> …` — т.е.
срабатывают, пока `#popCallStack` ещё в голове `<k>`, не применён. ⇒ на моменте декремента
`<callData>` = calldata **завершаемого** фрейма (селектор читается **до** pop). **Отступной путь
JUMPDEST не нужен** — монитор строится на существующих стыках `#mkCall`/`#return`.

### Механика (К4)

- `<inFunc> : Map(FuncSig4 → активных фреймов в C)` — сосед `<callCounter>` (вне `<ethereum>`,
  вне `<callState>`; то же trust-размещение, что T1-Q2b, ⇒ переживает revert-хранилище).
- `<monitoredAddr>` = адрес C; ставится клеймом ⇒ guard `callee==C` общий, без хардкода.
- **Инкремент** @`#mkCall` (evm.md:1678): `<inFunc> IF => #bump(IF, ACCTTO, MADDR, #selKey(ARGS), 1)`.
  `#bump` — тождество при `ACCTTO =/= MADDR`, поэтому guard `callee==C` не требует `requires` на
  штатном правиле (штатная применимость не меняется — A5). Ключ `#selKey(ARGS) =
  #asWord(#range(ARGS,0,4))` — селектор calldata НОВОГО фрейма.
- **Декремент** @3 стыках выхода: `<inFunc> IF => #bump(IF, CID, MADDR, #selKey(CALLDATA), -1)`,
  где `CID = <id>`, `CALLDATA = <callData>` завершаемого фрейма (до pop). **Revert-выход
  декрементит явно** — в отличие от кумулятивного `<callCounter>` (через revert не откатывается,
  T1-Q2b): `<inFunc>` стеко-привязан, ревертнутый фрейм больше не активен ⇒ обязан списаться.
- `reentered(sig) := <inFunc>[sig] >=Int 2`.

Diff (`diff repro/t1-q1/ii-mkcall/evm.md repro/t3-q0/evm.md`) — полностью аддитивный, LHS штатных
правил не тронут:
```
42a43,44        <inFunc> .Map </inFunc> ; <monitoredAddr> 0 </monitoredAddr>
290a293,320     helpers: #selKey / #ifGet / #bump  (total functions)
1684a1715,1716  #mkCall:      <inFunc> IF => #bump(IF, ACCTTO, MADDR, #selKey(ARGS), 1) ; <monitoredAddr> MADDR
1832a1865,1868  #return.exception:  <id> CID ; <callData> CALLDATA ; <monitoredAddr> MADDR ; <inFunc> IF => #bump(…,-1)
1842a1879,1882  #return.revert:     (idem)

```

### Честные оговорки (кандидаты в журнал Q4)

1. **Phantom-return (вне спеки мини-экземпляра).** Pre-фрейм-чеки `#checkBalanceUnderflow` /
   `#checkDepthExceeded` / `#checkNonceExceeded` (evm.md:1587/1605/1615) делают
   `#pushCallStack ~> #pushWorldState ~> #end` **без** `#mkCall`, затем возвращаются через
   `#return.exception`. Если C сам инициирует суб-вызов, падающий на таком чеке при активном
   C-фрейме (`<id>==C`), декремент переусчитывает. В withdraw-мини-экземпляре Pre это исключает
   (`EC₀ ≥ A` ⇒ нет balance underflow; глубина 2 ≪ 1024; CALL не бампит nonce), INV_inFunc держится
   в-спеке. Полный фикс — per-frame «entered-C» маркер, ставящийся `#mkCall` и снимаемый `#return`
   (4-й аддитивный стык). Отложено, зафиксировано.
2. **`entry-reenter` прогнан step-controlled** (`#mkCall` из уже-активного состояния — та же
   методика, что T1 Q1b), не полный байткод-самовызов (это Q1/Q3-уровень: нужен байткод withdraw +
   вся CALL-машинерия + газ). Демонстрирует достижение счётчиком 2 (reentered) на инструментированном
   стыке — ровно то, на что опирается INV_inFunc/reentered в Q1.

## Q1 — Кодирование и прогон матрицы obligations

**Вердикт:** `таблица T2 §6.2 держится в kprove: 17/17 клеймов = ожидание; V/F различаются ровно там,
где предсказал T2 (#3-strict, #6, #8 первичные + #10-global/#11 производные)`.

### Носитель кодировки (честно о границе)

Obligations закодированы над **абстрактной моделью** мини-экземпляра (`repro/t3-q1/withdraw.k`) —
state-уровень над ячейками `<balU>` (bal[U]), `<sumOth>` (Σ_{u≠U}bal[u]), `<ethC>` (balances[C]),
`<ethU>` (balances[U]), `<amt>` (A). Модель **верна по порядку операций** — единственная
дискриминирующая черта V/F (T2 §4.5): `withdraw_V = reqGE ~> susp ~> debit` (списание ПОСЛЕ внешнего
CALL), `withdraw_F = reqGE ~> debit ~> susp` (списание ДО). Полное байткод-замыкание «на форке T1» —
та же интеграционная граница, что T1-Q2a (raw kprove не авто-конфигурирует целый вызов до `#Top`);
конкретный on-fork дренаж — предмет Q3. Различие V/F **не зашито** — оно вытекает из порядка (ниже).

### Типизация рёбер (TCG-005 §4.2)

- `trusted-lemma` — #1, #2 (тело делает ≥1 SSTORE-шаг ⟹ ⊨⁺-узел; frame-property).
- `compat` — #3–#8 (R/G-импликация `Guar⟹Rely`; редукция T2 §4.1). Разряжается как одношаговая
  subsumption-проверка (механика T1-Q4): `#check=>#done`, содержание в `requires` (Guar) / `ensures` (Rely).
- `consequence` — #9, #10 (junction: `Post_i ⟹ INV` нулевого шага).
- `root` — #11 (сборка индукцией по PAR; **не отдельный клейм** — мета-вывод, см. ниже).

### Grounding: различие V/F вытекает из порядка операций (не постулируется)

Исполнение тела до точки приостановки (`#atSusp`) — `repro/t3-q1/q1-ground-spec.k`, оба **#Top**:
```
ground-V-pending-debit:  reqGE ~> susp ~> debit  =>  #atSusp ~> debit   ; <balU> B0 (не тронут)
ground-F-no-pending:     reqGE ~> debit ~> susp  =>  #atSusp            ; <balU> B0 -Int A (списано)
```
⇒ у V после suspension остаётся **pending debit**, и bal[U] всё ещё = B₀ ⟹ **Rely_w^V обязан фиксировать
bal[U]=B₀**. У F pending-записи нет ⟹ **Rely_w^F над bal[U] = ⊤**. Это и есть источник различения —
`временнáя привязка записи к точке приостановки` (T2 §4.5), добытая исполнением.

### Анти-false-green (где пусто доказательство — CLAUDE.md)

- **V-FAIL не spurious:** контрпримеры конкретны (реальная реентрантная транзиция ∈ Guar, ∉ Rely), а не
  BMC-рефутация из недостижимого состояния.
- **F-PASS не вакуумно:** антецеденты #6-F/#8-F **выполнимы** и **содержат тот же** реентрантный
  декремент bal[U] (`APRIME≥1`); F проходит потому, что Rely_w^F не ограничивает bal[U]. Контрфактический
  контроль `q1-vacuity-spec.k` (`logs/t3-q1-vacuity.log`): **та же транзиция F под СТРОГИМ Rely V →
  FAILED** (контрпример `#Not(B_PRE = B_PRE −Int APRIME)`). ⟹ проход F обусловлен именно силой Rely
  (добытой grounding'ом порядка операций), а не тривиальностью кодировки.

### #11 (root) — почему мета, а не отдельный прогон

Корневой solvency-INV `balances[C] ≥ Σ bal[u]` собирается **индукцией по PAR-правилу** (T2 §6.2, TCG-006 §3:
Reentrancy-as-self-interference) — это бумажная теорема A3b, не одиночный K-reachability-клейм. В kprove
прогоняются локальные куски: junction'ы #9/#10 (локальный INV сохраняется у обоих) + compat-пары #3–#8.
Для V корень **FAIL как следствие** FAIL на #6/#8/#3-strict (глобальная несостоятельность материализуется
через реентрантную цепочку, не локально — #10 локально зелёный у обоих). Для F — PASS (все #3–#8 зелёные).

## Q2 — Дискриминация V/F

**Вердикт:** `исход (a): дисциплина различает — #6 и #8: V FAIL, F PASS`. **Стоп-правило 1 НЕ сработало.**

Строго по матрице Q1. **Робастные дискриминаторы (К1) #6 (self-compat-withdraw) и #8 (env-compat-withdraw)
падают для V и проходят для F независимо от редакции Rely** — они привязаны к порядку списания
относительно точки приостановки (grounding выше), а не к силе Rely_w^V:
- V: реентрантный withdraw_V (Guar) уменьшает bal[U] после нашего CALL, а тело V ещё должно списать
  (pending debit) ⟹ Rely_w^V @ V2 нарушен ⟹ **FAIL**.
- F: списание уже произошло до CALL ⟹ Rely_w^F @ F3 над bal[U] = ⊤ ⟹ **PASS**.

**#3 — вторичный** (зависит от редакции, К1): V-strict FAIL / V-weak PASS; клейм дискриминации на него НЕ
опирается. Совпадение #3-weak у V и F **не** является беззубостью — критерий беззубости (TCG-006 §4
«мелкое»: правильная форма) — *ни одна* obligation не различает V/F; здесь различают #6, #8 (и #3-strict),
плюс производные #10-global, #11-root.

**Классификация:** `#6 и #8: V FAIL, F PASS` → **исход (a)** — дисциплина различает уязвимый и исправленный
код. Не «беззубость» (стоп-1), не «оба FAIL», не «падает не там». Дисциплина имеет зубы ⟹ Q3 (негкорпус)
осмыслен.

## Q3 — Негативный корпус: Guar_env против реальной атаки

### (a) Конкретный дренаж (Foundry, реальный EVM) — `repro/t3-q3/`

`Bank.sol`: `withdraw_V` (внешний CALL ДО записи ledger) / `withdraw_F` (запись ДО CALL). DAO-атакующий

терпима). Solc 0.8.35, `forge test` (`logs/t3-q3-forge.log`), **оба PASS**:

```

[PASS] test_F_safe()    — F: ре-вход видит balances[att]=0 -> revert; профита нет; 1 ETH жертвы цел
```
Трейс V-дренажа (`logs/t3-q3-forge-vtrace.log`, глубина ре-входа = 1, 2 перевода по 1 ETH):
```

├─ Bank::deposit{value: 1e18}()                 // E1  bank 1->2
├─ Bank::withdraw_V()                            // E2  outer C-frame; V2 переводит 1e18
│  └─ Attacker::receive{value: 1e18}()           // E3  env-код; C-frame приостановлен; bank.balance=1>=1
│     └─ Bank::withdraw_V()                       // E4  РЕ-ВХОД; inner C-frame; V2 переводит 1e18, bank->0
│        └─ Attacker::receive{value: 1e18}()      // E5  env-код; bank.balance=0<1 -> стоп
```

**Ghost-значения по трейсу** (селекторы `cast sig`: `withdraw_V()`=`0xd7eb2468`). `<inFunc>[wV]`: E2
`0->1`, E4 `1->2` — **`reentered(wV)` взводится ровно на ре-входе**; на возврате `2->1->0`. `<callCounter>`
кумулятивно +1 на каждый message-call (deposit, wV×2, receive×2). Механика на форке T1 доказана в
**Q0 `entry-reenter`** (`<inFunc>[SEL] 1→2`, `#Top`) — это on-fork носитель ghost-значения ре-входа; forge
исполняет сток-EVM (ghost-ячеек нет), поэтому значения тут аналитические, а их on-fork носитель — Q0.

### (b) Механический чекер допустимости Guar_env (декомпозированная форма, К3) — `repro/t3-q3/guarenv.k`

Каждый шаг трейса — либо `callIntoC` (атакующий зовёт публичный вход C: deposit/withdraw_V; в декомпозиции —
инстанциация loop/entry-claim, допустимо по §5.2 rows 1,3 «env может звать любой публичный вход, в т.ч.
незащищённый ре-вход»), либо `envCode` (собственный код атакующего между вызовами; допустим по env-step
**тогда и только тогда**, когда НЕ делает ничего из «не может» §5.2 rows A,B,C,E,F: прямой SSTORE в storage C,
подделка msg.sender, прямой слив native-баланса C кроме как через CALL к C, запись block-context, прямая
запись `<inFunc>`). Это **локальные проверяемые свойства шага**, НЕ темпоральная provenance-клауза.

Чекер (`allAdmissible : Steps -> Bool`) прогнан на трейсе (`--claims`, `logs/t3-q3-*.log`):

| claim | что | итог |
|---|---|---|
| `dao-trace-all-admissible` | весь трейс (E1..E5) → `allAdmissible => true` | **#Top** — все шаги допустимы |
| `fabricated-inadmissible-caught` | подставной env-шаг с прямым SSTORE в C (WSC=true) → `allAdmissible => false` | **#Top** — чекер ЛОВИТ недопустимый шаг |

Второй клейм — дискриминатор стоп-правила 2 и анти-вакуум: чекер не тривиальный `=> true`, он реально
возвращает `false`, если env-шаг требует запрещённого (прямой записи `S[C]`). Реальный EVM такого шага не
порождает ⟹ реальный трейс остаётся all-admissible ⟹ **стоп-правило 2 молчит**.

### Почему provenance-клауза не понадобилась (К3, ожидаемо — non-stop)

Декомпозированная форма покрыла ВЕСЬ трейс: изменения `S[C]` происходят только внутри `callIntoC`-шагов
(C-claims, легитимны по построению), а env-шаги проверяются **локально** (`WSC=false` и т.д.) — темпоральная
клауза «`S[C]` изменён только легитимными SSTORE фреймов C» НЕ кодировалась и не потребовалась. Это ровно
рекомендованный К3 путь (и будущая форма PAR-индукции). Монолитная форма — в журнал Q4 (не провал).

## Итог — решение по A3b

**Оба стоп-правила молчат.** Дисциплина различает V/F кодом (Q1/Q2: робастные #6/#8 = V-FAIL/F-PASS,
17/17 матрицы = ожидание T2); `Guar_env` допускает реальную DAO-атаку (Q3: все шаги допустимы, дренаж
реален, чекер дискриминирует) ⟹ модель врага не уже реальности на этом корпусе. Журнал Q4 непустой, но
все 4 зазора — **ожидаемые/несущественные** (provenance через декомпозицию К3; ∀-Users инвариантно к
формулам; H8 — соглашение кодировки; `-=`-консерватизм — sound, не unsound).

**Решение: A3b → ДОКАЗЫВАТЬ рамку (не пересматривать).** Формульные результаты T2 держатся под кодом;
негативный корпус подтвердил нижнюю планку адекватности `Guar_env`. Центральная лемма
Reentrancy-as-self-interference (TCG-006 §3) получила эмпирическую опору: различение держится на временнóй
привязке записи к точке приостановки (grounding Q1), ровно как постулировано.

**Границы (для продуктизации, не блокеры вывода):**
- Obligations прогнаны на **абстрактной модели** (порядок операций), не на полном байткоде на форке —
  та же интеграционная граница T1-Q2a (raw kprove не замыкает целый вызов). «Таблица держится в kprove» —
  на уровне R/G-импликаций, а on-fork ghost-носитель (Q0) + конкретный дренаж (Q3, forge) закрывают
  исполнительную сторону. Полное байткод-замыкание — Kontrol/форк-kdist (отдельный узел).
- `Guar_env` проверен на **одном** корпусе (канонический single-reentrancy DAO); «все допустимы» — нижняя
  планка, НЕ полнота. Кросс-функциональные / multi-Users атаки — вне текущего корпуса.
- Q4 #4: точная `-=`-форма T2 под 0.8 не дренит (underflow); R/G-флаг там консервативен. Для точности
  инварианта стоит зафиксировать, какую форму `withdraw_V` несёт боевой мини-экземпляр.
