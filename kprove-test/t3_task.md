# SPIKE-T3 — Сквозной прогон мини-экземпляра + негативный корпус (инженер)

**Проект:** Loop-based TCG. **Контекст спайка:** финальная фаза. T1 дал ghost-механику (закрыл C7), T2 дал интерфейсы withdraw-мини-экземпляра и снял оба kill-риска A3b на уровне формул. Эта задача проверяет формулы **кодом**: держится ли таблица obligations в реальном kprove и допускает ли Guar_env реальную атаку.
**Выход задачи = решение по A3b:** доказывать / пересматривать рамку.
**Стенд:** C9/T1 (kontrol 1.0.255 · K v7.1.337 · KEVM 1.0.678 · пиннован) + форк T1 (`<callCounter>` на `#mkCall`/`#mkCreate`).
**Входы:** t1_report.md (ghost-механика, repro/t1-*), spike_t2_report.md (§2 `<inFunc>`-спецификация, §3 интерфейсы, §4 self-compat, §5 Guar_env, §6 таблица obligations), TCG-006 (корректировки К1–К4 — обязательны к учёту).

---

**Контекст (2 абзаца для исполнителя):** T2 описал withdraw-паттерн в двух вариантах — уязвимом (V, перевод до списания) и исправленном (F, списание до перевода) — как таблицу из 11 R/G-obligations (TCG-006 §2 / spike_t2_report §6.2): frame-claims, попарные compat, self-compat (повторный вход), env-compat против Guar_env, junction'ы, корневой solvency-инвариант `balances[C] ≥ Σ bal[u]`. Задача — закодировать это в K-claims на форке T1 и получить матрицу фактических статусов против ожиданий T2.

Ключевое свойство — **дискриминация**: V обязан провалить self-compat (#6) и env-compat-withdraw (#8), F обязан пройти всё. Если оба проходят — дисциплина беззуба (худший исход). Если оба падают — невыразимость или ошибка кодировки. Вторая часть — негативная валидация Guar_env исполнением: реальная DAO-атака обязана быть *допустима* моделью врага, иначе модель тихо уже реальности и «гарантия» пуста.

**Прекондиция (T1-delta, выполнить первой):** реализовать `<inFunc>` по К4 — инкремент на существующем стыке `#mkCall` при `callee == C`, ключ = `callData[0..4]` создаваемого фрейма; декремент на 3 exit-стыках (`#return.normal`, `#return.revert`, `#halt`) с чтением `<callData>` завершаемого фрейма ДО pop. Тот же класс аддитивных правок, что `<callCounter>` (T1 §Q1). Отступной путь, если селектор не читается на exit до pop: первый `JUMPDEST` фрейма (T2 §2). Зафиксировать, какой путь сработал.

**Q0 — `<inFunc>` реализация [прекондиция]**

Реализовать монитор по К4. Проверить инвариант INV_inFunc (T2 §2): `<inFunc>[sig]` = число фреймов в call-stack с этим селектором. Toy-прогон: вложенный самовызов C.withdraw глубины 2 → `<inFunc>[sig_withdraw] == 2` на дне, `reentered(sig) ≜ <inFunc>[sig] ≥ 2` взводится.

**Формат:** `реализовано (какой путь: #mkCall / JUMPDEST) · diff · PROVED reentered на глубине 2` + лог. Если ни один путь не читает селектор — стоп, вернуть немедленно (меняет форму монитора T2).

**Q1 — Кодирование и прогон матрицы obligations [ядро]**

Закодировать все 11 obligations (T2 §6.2) в K-claims на форке, типизация рёбер по TCG-005 §4.2 (`trusted-lemma` / `consequence`). Прогнать для V и F. **По К1** — для #3 (compat-dep→with) прогнать ОБЕ редакции Rely_w^V: строгую (`bal[U] = B₀`) и ослабленную (`bal[U] ≥ B₀`); зафиксировать статус каждой. Любое отклонение кодировки от формул T2 — фиксировать с причиной (сигнал о выразимости, Q4).

**Формат:** матрица `# · obligation · тип ребра · ожидание(T2) · факт V · факт F · расхождение`; для #3 — две строки (строгая/ослабленная Rely). Для каждого FAILED — контрпример/застрявшая конфигурация из лога.

**Q2 — Дискриминация V/F [критерий выхода]**

Вердикт строго по матрице. **Робастные дискриминаторы (К1): #6 (self-compat-withdraw) и #8 (env-compat-withdraw)** — они обязаны падать для V и проходить для F независимо от редакции Rely. #3 — вторичный (зависит от редакции). Классифицировать исход:
- `#6 и #8: V FAIL, F PASS` → дисциплина различает, исход (a);
- `V и F совпали на #6/#8` → беззубость, **стоп-правило 1**;
- `оба FAIL` → разбор: невыполнимость против ошибки кодировки (приложить анализ застрявшей конфигурации);
- `падает не там / не так` → описать точно.

**Q3 — Негативный корпус: Guar_env против реальной атаки [риск №2 исполнением]**

Минимальный DAO-класс атакующий (receive/fallback с повторным вызовом withdraw_V) против V. (a) Конкретное исполнение (Foundry/anvil) — атака реально дренит контракт, трейс зафиксирован (шаги: вызовы, value, глубина ре-входа, значения `<callCounter>`/`<inFunc>`). (b) Каждый шаг атакующего из трейса проверяется на допустимость формулой Guar_env (T2 §5, **декомпозированная форма по К3**): env-step покрывает сегменты без активных C-фреймов, ре-входы — инстанциацией loop-claim. Механический чекер: шаг трейса → предикат Guar_env → допустим/нет.

**По К3:** сначала пробовать декомпозированную форму Guar_env (env-step без активных C-фреймов + loop-claim на ре-входах). Монолитную форму с provenance-клаузой (`S[C] изменён только легитимно`) кодировать ТОЛЬКО если декомпозиция не покрывает трейс; если монолитная provenance-клауза не выражается в K-`requires` — это результат (журнал Q4), не провал.

**Формат вердикта:** `все шаги атаки допустимы Guar_env (декомпозированная) | шаг K недопустим (какое ограничение ложно) | provenance-клауза невыразима (журнал)`.
**Критерий:** «все допустимы» → Guar_env не уже реальности на этом корпусе (нижняя планка адекватности; полноту не утверждаем). «Недопустим» → формула уже реальности, чинить до выводов о теореме.

**Q4 — Журнал зазоров выразимости [обязательный побочный]**

Всё, что T2-формулы требовали, а K-claims не выразили без искажения: конструкция → чем заменена → что потеряно. Обязательные кандидаты (из TCG-006): provenance-клауза Guar_env (К3), Rely на интервале приостановки (наблюдаемость env-транзиций), универсальная квантификация по Users. Пустой журнал — валидный результат.
